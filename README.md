## 一、網站原則（為什麼長這樣）

**這個網站是做什麼的**
讓台灣表演團隊的團長、帶團老師認識路橋，然後**加 LINE 預約免費「出國健檢」**。
整個網站只有這一個目標動作。任何修改都要問：這會讓團長更想加 LINE，還是更不想？

**誰在看**
團長、帶團老師、家長會。不懂行政術語、大多用**手機**看、很可能是從 LINE 群組點進來的。

**我們是誰**
「你的團的國際事務部」——幫團隊處理國際邀約、立案、補助企劃、隨團統籌。團隊專心排練，出國的事交給我們。

**語氣**
像一位可靠的前輩在說話：白話、短句、具體。不浮誇、不用行話、不用英文縮寫。

## 二、文案原則（人跟 AI 都要遵守）

1. **只寫做過、可以證明的事。** 案例數字「31 天・4 個國際藝術節・20 餘個城鎮・9 國團隊」已跟藝姿舞集確認過。要改數字或加新案例，先確認資料來源。
2. **角色照實寫。** 2026 葡西巡演 Lucio 的角色寫「隨團翻譯與當地對接」。要換成更大的頭銜，先取得藝姿團長同意。
3. **補助只寫「申請過」。** 核定結果公告前，不寫「拿到」「獲得」「通過」。
4. **網站不放價格。** 費用只寫「以協助取得的補助為基礎；初次健檢免費」。
5. **不寫代訂機票、住宿。** 那需要旅行業執照，我們不做這項。
6. **團隊區目前只放 Lucio 一人。** 其他夥伴寫一行「依巡演規模編組」，有實際合作的案子再加人。
7. **服務對象刻意寫寬。** 民俗舞蹈、合唱、國樂絲竹、原住民樂舞、武術藝陣、青年樂團、戲曲劇場；國小到大學的校園團隊，以及社區、半職業團隊。不要縮成「只服務舞團」。
8. **固定不改的字**：名稱「路橋巡演工作室／LU BRIDGE TOURING STUDIO」、標語「讓世界看見，你們的舞台」「從排練場，到國際藝術節」。

## 三、照片與影片原則

9. **只用團方同意公開的照片。** 照片裡有未成年團員，新照片上網前先跟團方確認，最好在 LINE 留文字紀錄。
10. **案例照片要看得出「在國外、在舞台、在交流」。** 團長最想看到的是「我的團在國外舞台上的樣子」。
11. **影片先確認配樂是免版稅**才放（市售歌曲會被檢舉或靜音）。影片上傳到 YouTube 再嵌進網頁，**不要把影片檔直接放進這個倉庫**。

## 四、設計原則

12. **風格是「藝術節海報」**：米白底、紅日（紅色大圓）、藍環（藍色細圓圈）、特大明體標題、黑色粗框。
13. **顏色只用這幾個**（定義在 `index.html` 最上方的 `:root`），不要另外加新顏色：
    米白 `#F4F2EC`、紙白 `#FCFBF8`、墨黑 `#21201C`、紅 `#D8452E`、藍 `#2C4FA3`、灰字 `#6B675C`。
14. **手機優先。** 改完一定要用手機看一次：畫面不能左右滑、字不能壓在紅色圓上看不清楚、按鈕要大到手指按得到。
15. **每一屏最多一個重點**，留白比塞滿重要。

## 五、技術原則（給 AI 看的，Lucio 不用懂）

16. **整個網站就是一個 `index.html`＋`img/` 資料夾。** 保持這樣：不要改成需要「建置」的框架（React、Next.js、Tailwind 建置等），不要加 npm 套件。誰都要能直接打開 `index.html` 改字。
17. **這個倉庫是公開的**，任何人都看得到。只放網站本身的檔案。收費、補助研究、合約、個人資料等內部文件**絕對不要放進來**。
18. **LINE 按鈕有 4 個**（首頁、服務區、聯絡區的按鈕，加上聯絡區的 LINE ID 連結），都連到 `https://line.me/ti/p/~luciokuo8831`。換 LINE 帳號時 4 個一起換。
19. **版號**：`index.html` 開頭有 `<!-- 路橋網站 v5.0 -->`。每次改網站內容就往上加（v5.1、v5.2…），存檔說明也寫上版號和改了什麼。
20. **照片規格**：檔名用英文小寫、不要空格（例如 `case-stage-2.jpg`）；大圖寬 1600px、小圖 800px；JPG；單張盡量 500 KB 以內；`alt` 用一句中文描述照片內容。
21. **不要刪 `.nojekyll`**（讓 GitHub 原樣發布網站）。

## 六、怎麼改網站

### 方法一：直接在 GitHub 網頁上改（改幾個字最快）
1. 登入 GitHub（帳號 `lubridge1999`），打開這個倉庫
2. 點 `index.html` → 右上角的**鉛筆圖示**
3. 按 Ctrl+F（Mac 是 Cmd+F）找到要改的字，直接改
4. 按右上角綠色 **Commit changes**，說明欄寫「v5.1 改了什麼」，再按一次確認
5. 等 1–2 分鐘，重新整理網站確認

### 方法二：叫 AI 改（改版面、加區塊、換照片）
1. 用 AI 工具連上這個 GitHub 倉庫（例如 Claude 的 Code 功能，連結 GitHub 帳號 `lubridge1999` 後選 `lubridge1999.github.io`）
2. 用中文說你要改什麼，例如「FAQ 加一題：可以只出國交流、不比賽嗎？答案是…」
3. AI 改完會告訴你改了哪裡。如果它開了一個 **Pull Request**，要按 **Merge** 才會真的上線
4. 等 1–2 分鐘，用手機打開網站確認

只有聊天型 AI（不能連 GitHub）也可以：把這份 README 和 `index.html` 一起丟給它，請它回傳「改好的完整 index.html」，再用方法一整份貼回去。

### 改壞了怎麼辦
不用怕，每一次存檔 GitHub 都會留紀錄，可以退回任何一個舊版本。跟 AI 說「把網站退回上一個版本」，或請夥伴幫忙。

### 哪些可以直接改、哪些要先討論
- **直接改**：錯字、換照片、更新數字（確認過的）、FAQ 小修
- **先跟夥伴對過再上線**：新增或刪除區塊、改標語、改服務項目、改職稱、加新案例

## 七、給 AI 的工作規則

如果你是被請來修改這個網站的 AI：

1. 先讀完這份 README，所有修改都要符合上面的原則。要求跟原則衝突時（例如要寫價格、要宣稱拿過補助），**先停下來說明衝突，請使用者確認**，不要自己決定。
2. 使用者不是工程師。**用白話中文說明**你改了什麼、為什麼，不要用術語；需要他做的步驟（例如按 Merge），一步一步寫清楚。
3. 只改被要求的地方，不要順手重構、重新排版或改寫其他文案。
4. 改完自己檢查：手機寬度（375px）不能左右滑、所有照片路徑存在、4 個 LINE 連結都還在、`index.html` 開頭的版號有往上加。
5. 不要新增框架、套件或建置步驟；不要把內部文件、密碼、個人資料放進倉庫。
6. 改的是**網址**相關設定時（換網域），記得一起改 `index.html` 開頭的 `canonical`、`og:url`、`og:image` 三個網址。

## 附錄

**檔案在哪**

| 檔案 | 是什麼 |
|---|---|
| `index.html` | 整個網站。上方 `<style>` 是樣式，下面依序是：首頁大標 → 服務（`#service`）→ 案例（`#case`）→ 團隊（`#team`）→ 常見問答 → 聯絡（`#contact`）→ 頁尾 |
| `img/` | 網站照片；`share.jpg` 是分享到 LINE／Facebook 時出現的預覽圖（1200×630） |
| `.nojekyll` | 讓 GitHub 原樣發布網站，不要刪 |
| `README.md` | 這份說明 |
| `CLAUDE.md`、`AGENTS.md` | 給 AI 工具的入口，內容是「先讀 README」 |

**分享預覽**：網址貼到 LINE／Facebook 時，會出現 `img/share.jpg`，加上 `index.html` 開頭 `og:` 那幾行的標題和描述。LINE 會暫存預覽，改了之後可能要等一陣子才會更新。

**換成自己的網域時**
1. 這個倉庫的 Settings → Pages → Custom domain 填上網域，勾選 Enforce HTTPS
2. 到網域商設定指向 GitHub（照 GitHub 官方說明：https://docs.github.com/pages/configuring-a-custom-domain-for-your-github-pages-site ）
3. 改 `index.html` 開頭 `canonical`、`og:url`、`og:image` 三個網址
